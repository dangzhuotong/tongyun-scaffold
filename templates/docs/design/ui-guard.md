# 界面守则检查清单

在修改或新增界面时，必须依照本清单逐项自查，确保视觉与交互的一致性。

新建 UI 遵循本清单；已有产品的实物和 DESIGN.md 优先，不因接入规范一次性回改手帐。`--ui` 生成资产见 `ui/README.md`，主题取值以项目选择为准。

## 令牌优先

- [ ] **严禁字面值**：颜色、圆角、内边距与间距等样式仅使用设计令牌（Tokens），不写硬编码数值。
- [ ] **取值基准**：令牌数值统一遵循根目录 [DESIGN.md](../../DESIGN.md)（由 `tongyun-ui-design` 或 `tongyun-product/jobs/project` 生成；若缺失则先创建）。
- [ ] **同级复用**：添加新样式前，优先复用相邻同级页面的既有取值与结构。

## 字体

- [ ] **字号收敛**：仅使用预设的有限几档字号阶梯。
- [ ] **字重上限**：字体粗细最大不超过 500（`font-weight <= 500`）。
- [ ] **强调方式**：重点信息通过字号层级或文字颜色区分，不使用更重的粗体强调。

## 复用

- [ ] **组件优先**：优先复用或扩展现有组件，避免重复创建功能相近的组件。
- [ ] **图标收敛**：图标仅能选用项目已引入的图标集。
- [ ] **变更核验**：新增组件遵循 DESIGN.md，记录复用理由并验证实际交互、键盘和主题；图标采用既有图标集。

## 反馈位置

- [ ] **全局反馈**：一次性的通用操作成功或失败提示，使用全局 Toast。
- [ ] **就地报错**：与当前表单或交互表面直接绑定的错误，在对应位置就地（in-place）呈现。
- [ ] **保留数据**：操作失败时保持当前已有数据与输入内容可见，禁止直接清空。
- [ ] **文案清晰**：报错文案控制在 1–2 句通俗语言，说清发生了什么以及如何处理。

## 加载

- [ ] **可理解的等待**：按内容选择骨架、指示器或加载文字；提供可读状态及 aria-busy，不只靠动画表达，同一任务避免重复等待提示。

## 浮层（菜单 / 气泡 / 对话框）

- [ ] **快捷退出**：菜单支持外部点击和 Esc；模态对话框提供明确关闭及 Esc、焦点恢复。含未保存输入或危险确认时，外部点击策略由业务决定，避免误关丢失输入。
- [ ] **视口内适配**：弹层必须完整容纳在视口内部，不产生意外的屏幕外溢出。
- [ ] **防截断遮挡**：正确设置层叠上下文，避免被父级容器的 `overflow` 或 `z-index` 截断。

## 主题

- [ ] **双主题核验**：合并前必须在浅色模式与深色模式下分别验证，确保可读性与视觉正常。

## 合并前自查

- [ ] 页面无硬编码样式数值，已全部对齐设计令牌。
- [ ] 浅色与深色主题下视觉对比度正常。
- [ ] 浮层、弹窗及下拉框在各视口尺寸下均无截断、错位或无法关闭的问题。
- [ ] 异常反馈与空状态文案通俗清晰，失败时保留用户输入。

思路参考 deepseek-ai/deepseek-harness（MIT）的界面规则，按通用项目重写。
